# 05 credential 與美譽值的關係

> 簡介段：本篇承接 [01-meritoken-overview.md](./01-meritoken-overview.md) 的位置定義，在「契約部件」語義下，專門處理美譽值（MeriToken）與 `credential` 之間的邊界與對位關係。兩者經常被混用，但在新社會的協作實務中如果不分清，會同時削弱身分與權屬的穩定性、以及貢獻與評價的可累計性。

## 背景

新社會中關於「我是誰」「我能不能做這件事」「我做過什麼」「我做得怎麼樣」這幾個問題，必須有結構上彼此獨立、又能互相組合的承載對象。如果把所有問題都堆給一類對象去回答，就會出現兩類典型偏差：

- **憑據膨脹**：把「我做過什麼、做得怎麼樣」也寫進 `credential`，使得身分與權屬憑據被迫不斷簽發與更新，憑據簽發方負擔過重，憑據持有方也失去對自己評價記錄的支配權。
- **評價漂移**：把「我是誰、我有什麼權屬」也寫進美譽值，使得貢獻評價的容器被身分屬性擠占，原本應當由協作多方共簽的評價記錄被身分簽發權所稀釋。

藍圖把這兩類對象分開承擔，並明確：`credential` 解決「身分與權屬」一面，美譽值解決「貢獻與評價」一面。兩者各自獨立又彼此對位。本篇的任務是把這條邊界講清楚，避免後續 06–07 篇與各語言扇出版本在引用時出現混用。

`credential` 的具體協議層細節由 ifay 體系的官方文件承擔，本篇只在「與美譽值邊界」必要的範圍內給出最小說明。

## 核心內容

上圖（暫複用）刻畫了 `credential` 在簽發、驗證、回收鏈路上的基本動作。本篇的討論建立在這一動作集之上，把它與美譽值的「貢獻—評價」語義並置。

### credential 的角色定位

`credential` 解決「主體是誰、對什麼對象擁有什麼權屬」這一類問題，是新社會中身分與權屬的承載憑據：

- **身分與權屬的可證明位**：`credential` 由具備簽發資格的主體簽發，記錄被簽發主體的身分屬性（如成員身分、角色、資格）或對特定對象的權屬（如對某資源、某協議位、某協議角色的支配權）。它回答的是「這位主體在某一時點對某一對象處於什麼權屬狀態」。
- **由憑證與代幣層簽發、驗證、回收**：`credential` 的生命週期由憑證與代幣層的協議規則約束。簽發動作明確了其有效範圍；驗證動作讓任意第三方可以獨立確認憑據的存在與歸屬；回收動作讓簽發方在權屬變更時能夠及時收回憑據，避免憑據脫離實際權屬繼續被援引。
- **側重於「能做什麼」的入口資格**：在跨主體協作中，`credential` 通常作為入口資格被檢視：被檢視方持有相應 `credential`，意味著它在制度上具備進入某一協作面、援引某一協議位、呼叫某一資源介面的資格。`credential` 不直接評價被檢視方過去做得如何。
- **穩定性優先**：`credential` 的語義穩定性是其根本屬性。一份長期有效的成員資格、一份對某資源的支配權，不會因為持有方短期內的協作表現而頻繁波動；波動的部分應當由美譽值承載，而不是反映回 `credential`。

把 `credential` 的角色鎖定在「身分與權屬憑據」這一面，是為了讓憑據的簽發與回收路徑保持簡潔可審計，不被頻繁的評價記錄所干擾。

### 美譽值（MeriToken）的角色定位

美譽值解決「主體做過什麼、被如何評價」這一類問題，是新社會中貢獻與評價記錄的承載對象：

- **貢獻與評價的可累計位**：美譽值由協作多方共簽產生（詳見 [02-meritoken-technical.md](./02-meritoken-technical.md) 的「加密」與「取用」段），記錄的是「在某一具體協作中，誰貢獻了什麼、誰見證了什麼、誰如何評價」。它回答的是「這位主體過去在哪些具體協作中表現如何」。
- **從屬於 `GMC` 上位體系**：與 `credential` 的簽發—回收鏈路不同，美譽值的產生—引用—撤回鏈路在 `GMC` 上位體系下統一記帳，按鏈式語義保證全網一致與不可篡改（詳見 [01-meritoken-overview.md](./01-meritoken-overview.md) 的「美譽值（MeriToken）與 `GMC` 的從屬關係」段）。
- **側重於「做過什麼、做得怎麼樣」的過程留痕**：美譽值不充當入口資格的檢驗，而是在協作過程中持續生成。它對外可以被援引、被聚合、被對照，但每一條都對應具體的協作事實，不可憑空增減。
- **可累計、可撤回、可分級披露**：美譽值在長期協作中累計形成多維度成長畫像；當原始約定改變時，被引用方可以撤回相應披露許可；任何引用都按 `GMC` 留痕（詳見 [02-meritoken-technical.md](./02-meritoken-technical.md) 的「隱私保證」段）。

把美譽值的角色鎖定在「貢獻與評價記錄」這一面，是為了讓協作過程的細粒度評價能夠長期累計、獨立支配，不被身分簽發權所兼併。

### 邊界與對位關係

`credential` 與美譽值在新社會的協作中各自承擔不可互相替代的角色。下表沿五條語義軸並置兩者的差異：

| 語義軸 | `credential` | 美譽值（MeriToken） |
|--------|--------------|---------------------|
| 語義焦點 | 身分與權屬憑據，回答「主體是誰、對什麼對象擁有什麼權屬」 | 貢獻與評價記錄，回答「主體在哪些協作中做過什麼、被如何評價」 |
| 生命週期 | 由憑證與代幣層簽發、驗證、回收，強調入口資格的狀態切換 | 由 `GMC` 上位體系記帳，產生—引用—撤回鏈路按鏈式語義留痕 |
| 持有形態 | 由簽發方與持有方雙向錨定的狀態對象，強調穩定性 | 由協作多方共簽的過程對象，強調累計性 |
| 引用方式 | 在協作入口處被檢視，驗證「是否具備資格」 | 在協作過程或事後被援引、聚合、對照，呈現「過去做得如何」 |
| 跨主體語義 | 同一主體在不同協作面持有不同 `credential`，相互之間不一定可比 | 同一主體在不同議題上累計的美譽值條目可被跨議題引用，但不會自動遷移評價權重 |

邊界在四個層面互相支撐，確保兩類對象不被混用：

- **不可互相替代**：`credential` 不能用來記錄「我做過什麼、做得怎麼樣」，否則就會出現憑據膨脹與簽發方負擔失衡；美譽值不能用來記錄「我是誰、我有什麼權屬」，否則會出現評價漂移與所有權稀釋。兩者各自承擔不同的制度任務。
- **互為前提與延展**：在很多協作中，`credential` 提供入口資格，美譽值在入口之內沉澱過程留痕。例如某項跨組織議事，`credential` 決定參與方是否具備發言資格；美譽值則記錄每一次發言的貢獻與評價，長期累計後影響後續議題的發言權重（參見 [03-meritoken-social.md](./03-meritoken-social.md) 的「政治邏輯」段）。
- **統一引用、分別承載**：在 `Fay` 主體的代理式與聚合式引用（詳見 [04-meritoken-usage.md](./04-meritoken-usage.md) 的「`Fay` 主體的引用方式與應用場景」段）中，對外往往同時呈現一組 `credential` 與一組美譽值條目。前者用於證明 `Fay` 主體具備代表權，後者用於呈現其歷史協作面貌；兩者並列引用而非合併。
- **撤回路徑獨立**：`credential` 的回收由簽發方按權屬變更觸發；美譽值的撤回由被引用方按披露許可觸發。兩條撤回路徑不應互相代償——簽發方不能透過收回 `credential` 抹除已經被見證的美譽值條目；被引用方也不能透過撤回美譽值披露反推簽發方收回 `credential`。
