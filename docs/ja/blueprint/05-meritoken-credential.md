# 05 credential と MeriToken の関係

> 概要：本編は [01-meritoken-overview.md](./01-meritoken-overview.md) の位置づけ定義を引き継ぎ、「契約部品」意味論の下で、MeriToken と `credential` の境界および対応位置づけを専門に扱う。MeriToken と `credential` はしばしば混用されるが、新たな社会の協働実務において区別を曖昧にすると、身元と権属の安定性、ならびに貢献と評価の累積可能性を同時に削いでしまう。

## 背景

新たな社会において「自分は誰か」「自分はそれをしてよいか」「自分が何をしたか」「自分はどう評価されたか」という問いに対しては、構造上互いに独立しつつも組み合わせ可能な担い手が必要となる。すべての問いを一種類の対象に押し付けると、典型的に二つの偏向が生じる：

- **資格情報の肥大化**：「自分が何をしたか、どう評価されたか」までを `credential` に書き込もうとすると、身元と権属の資格情報が絶え間なく発行・更新され、発行側の負担が過度になり、保持側も自身の評価記録に対する支配権を失う。
- **評価の漂流**：「自分は誰か、何の権属を持つか」までを MeriToken に書き込もうとすると、貢献評価の容器が身元属性に侵食され、本来は協働の多者共同署名で支えるべき評価記録が発行権限によって希釈される。

ブループリントはこの二類の対象を別々の担い手に分配する。`credential` は「身元と権属」の側を解決し、MeriToken は「貢献と評価」の側を解決する。`credential` と MeriToken は各自独立しつつも互いに対応する。本編の任務はこの境界を明瞭化し、後続の 06–07 編および各言語版において参照時に混用が生じないようにすることにある。

`credential` の具体的なプロトコル層の詳細は ifay 体系の公式ドキュメントが担い、本編では「MeriToken との境界」に必要な範囲でのみ最小限の説明を与える。

### credential の役割定位

`credential` は「主体は誰か、どの対象に対していかなる権属を有するか」という問いを解決し、新たな社会における身元と権属の担い手たる資格情報である：

- **身元と権属の証明可能なビット**：`credential` は発行資格を持つ主体により発行され、被発行主体の身元属性（メンバーシップ、役割、資質等）または特定対象に対する権属（あるリソース、あるプロトコルビット、あるプロトコル上の役割への支配権）を記録する。それが答えるのは「この主体が、ある時点で、ある対象に対してどのような権属状態にあるか」である。
- **資格情報・トークン層により発行・検証・回収される**：`credential` のライフサイクルは資格情報・トークン層のプロトコルルールにより制約される。発行行為はその有効範囲を定める。検証行為は任意の第三者がその存在と帰属を独立に確認しうるようにする。回収行為は発行側が権属の変更時に資格情報を速やかに引き戻すことを可能にし、資格情報が実際の権属から離れて援用され続けることを防ぐ。
- **「何ができるか」の入場資格に重きを置く**：主体間の協働において、`credential` は通常入場資格として吟味される。被吟味側が対応する `credential` を保持していることは、当該協働面に入る、当該プロトコルビットを援用する、当該リソースインタフェースを呼び出すことの制度的な資格を備えていることを意味する。`credential` は被吟味側の過去の振る舞いを直接評価しない。
- **安定性の優先**：`credential` の意味論的安定性はその根本属性である。長期に有効な構成員資格、あるリソースに対する支配権は、保持側の短期的な協働の振る舞いによって頻繁に揺れ動かされない。揺れ動きは MeriToken が担うべきであり、`credential` に反映してはならない。

`credential` の役割を「身元と権属の資格情報」の側に固定するのは、資格情報の発行と回収の経路を簡潔かつ監査可能に保ち、頻繁な評価記録に攪乱されないようにするためである。

### MeriToken の役割定位

MeriToken は「主体が何をしたか、どう評価されたか」という問いを解決し、新たな社会における貢献と評価の記録の担い手である：

- **貢献と評価の累積可能なビット**：MeriToken は協働の多者共同署名により生成され（詳細は [02-meritoken-technical.md](./02-meritoken-technical.md) の「暗号化」「取得」節）、「ある具体的な協働において、誰が何を貢献し、誰が見届け、誰がどう評価したか」を記録する。MeriToken が答えるのは「この主体が過去のどの具体的な協働でどう振る舞ったか」である。
- **`GMC` 上位体系に従属する**：`credential` の発行—回収経路とは異なり、MeriToken の生成—参照—撤回経路は `GMC` 上位体系の下で統一的に記帳され、チェーン的意味論によりネットワーク全体での整合と改竄不能性が保証される（詳細は [01-meritoken-overview.md](./01-meritoken-overview.md) の「MeriToken と `GMC` の従属関係」節）。
- **「何をしたか、どう振る舞ったか」の過程の記録に重きを置く**：MeriToken は入場資格の検査ではなく、協働の過程で持続的に生成される。対外的には援用、集約、対照されうるが、各エントリは具体的な協働事実に対応し、無からの増減はできない。
- **累積可能、撤回可能、段階的に開示可能**：MeriToken は長期協働において累積し、多次元的な成長像を形成する。当初の合意が変わった場合、被参照側は対応する開示の許諾を撤回できる。すべての参照は `GMC` の記録に従う（詳細は [02-meritoken-technical.md](./02-meritoken-technical.md) の「プライバシー保証」節）。

MeriToken の役割を「貢献と評価の記録」の側に固定するのは、協働過程の細粒度の評価が長期に累積し、独立に支配されるようにし、発行権限に併呑されないようにするためである。

### 境界と対応位置づけ

`credential` と MeriToken は新たな社会の協働においてそれぞれ互いに置換できない役割を担う。次の表は五つの意味軸に沿って `credential` と MeriToken の差異を並置する：

| 意味軸 | `credential` | MeriToken |
|--------|--------------|-----------|
| 意味の焦点 | 身元と権属の資格情報。「主体は誰か、どの対象にどの権属を有するか」を答える | 貢献と評価の記録。「主体がどの協働で何をしたか、どう評価されたか」を答える |
| ライフサイクル | 資格情報・トークン層により発行・検証・回収され、入場資格の状態切替を強調 | `GMC` 上位体系で記帳され、生成—参照—撤回経路はチェーン的意味論に従い記録される |
| 保持形態 | 発行側と保持側で双方向に固定される状態オブジェクト。安定性を強調 | 協働の多者共同署名により形成される過程オブジェクト。累積性を強調 |
| 参照方法 | 協働入口で吟味され、「資格を備えるか」を検証する | 協働の過程または事後に援用、集約、対照され、「過去にどう振る舞ったか」を提示する |
| 主体間の意味論 | 同一主体が異なる協働面で異なる `credential` を保持し、相互に必ずしも比較可能ではない | 同一主体が異なる議題で累積した MeriToken エントリは議題横断で参照可能だが、評価の重みは自動的には移行しない |

境界は四つの層で互いに支え合い、二類の対象が混用されないようにする：

- **互いに置換不能**：`credential` は「自分が何をしたか、どう評価されたか」の記録に用いてはならない。さもなければ資格情報の肥大化と発行側負担の不均衡が生じる。MeriToken は「自分は誰か、何の権属を持つか」の記録に用いてはならない。さもなければ評価の漂流と所有権の希釈が生じる。`credential` と MeriToken はそれぞれ異なる制度的任務を担う。
- **互いの前提と延長**：多くの協働で `credential` が入場資格を提供し、MeriToken が入場後に過程の記録を沈殿させる。例えばある組織横断的議事では、`credential` が参加側に発言資格があるかを決め、MeriToken が各発言の貢献と評価を記録する。長期に累積した記録は後続議題の発言重みに影響する（[03-meritoken-social.md](./03-meritoken-social.md) の「政治論理」節を参照）。
- **統一参照、別個の担い手**：`Fay` 主体の代理型・集約型参照（詳細は [04-meritoken-usage.md](./04-meritoken-usage.md) の「`Fay` 主体の参照方法と応用シーン」節）では、対外的に `credential` のセットと MeriToken エントリのセットを同時に提示することがしばしばある。前者は `Fay` 主体が代表権を備えていることを証明し、後者はその過去の協働の様相を提示する。両者は並置参照されるが、合体はしない。
- **撤回経路の独立**：`credential` の回収は発行側が権属の変更によりトリガーする。MeriToken の撤回は被参照側が開示の許諾によりトリガーする。両撤回経路は互いに代償しない。発行側が `credential` を引き戻すことですでに見届けられた MeriToken エントリを抹消することはできず、被参照側が MeriToken の開示を撤回することで発行側に `credential` の回収を強いることもできない。

## 用語脚注

本書に登場する `Reserved_Term`：

- **credential**：個人または `Fay` 主体の身元と権属を裏付ける資格情報。詳細は [glossary.md](./glossary.md) を参照。
- **GMC**：Global Merit Chain、MeriToken の上位体系。詳細は [glossary.md](./glossary.md) を参照。
- **Fay**：非個人主体の MeriToken 参照者。詳細は [glossary.md](./glossary.md) を参照。
- **ifay**：プロジェクト体系の名称。詳細は [glossary.md](./glossary.md) を参照。

MeriToken の中国語主称呼は `zh-CN` と `zh-TW` のブループリント本文においてのみ MeriToken の通常呼称として用いられる。詳細は [glossary.md](./glossary.md) の `Localized_Term` 節を参照。
