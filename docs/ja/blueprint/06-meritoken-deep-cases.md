# 06 MeriToken の発展テーマ

> 概要：本編は MeriToken テーマ集の拡張枠であり、[01-meritoken-overview.md](./01-meritoken-overview.md) から [05-meritoken-credential.md](./05-meritoken-credential.md) までのすべての先行合意を引き継ぎ、新たな社会における MeriToken の二類の高密度利用情境——「主体間協働における MeriToken の高密度利用」と「ローリングシーン」——を独立したテーマとして展開する。各テーマは主線で既述の概念を繰り返さず、主線の機構を具体的な負荷の場面に置き直して観察し直す。

## 背景

主線の 01–05 編では、MeriToken の位置づけ、技術原理、社会的含意、参照と応用、`credential` との境界を述べた。しかし新たな社会で実際に運用が始まると、主線の論述だけでは直接覆いきれない二類の「高負荷」情境が浮上する：

- **主体間の高密度利用**：複数の `Fay` 主体と複数の個人主体が同一議題下で持続的に MeriToken を参照する状況では、単一の参照は単純に見えても、それらが累積するとオーバーヘッド、開示、集約という三類の難題が立ち現れる。
- **ローリングシーン**：協働のライフサイクルが十分に長い場合、MeriToken は一度限りの成果物の記録ではなく、複数ラウンドの累積、修正、撤回、アーカイブの循環を経ることになる。これは MeriToken の機構が長時間スケールで自己整合的であることを要求し、単発参照で合理的に見えるだけでは足りない。

本編はこの二類のテーマをそれぞれ展開する。各テーマでは、まず負荷の源を簡潔に述べ、続いて主線の機構（取得、開示、記録、所有権と使用権、`credential` の境界等）をその負荷の下に置き直して再吟味し、後続の論証や工程化に値する未解決点を指摘する。本編では新たなプロトコル層概念は導入せず、すべての内容は主線で定義済みの機構の新たなシーンへの推論に過ぎない。

## 核心内容

### テーマ A：主体間協働における高密度利用

**負荷の源**：新たな社会の現実の協働では、「ある `Fay` 主体が一つの MeriToken を参照する」という状況はあまりにも理想化された最小情境である。実際にもっと頻繁なのは、同一議題下で次の三類の参照源が同時に出現する状況である——

- **複数の `Fay` 主体**：例えば異なる業界、異なる地域の協働各方が、それぞれ自身のメンバーを代表して関連する MeriToken を参照する；
- **複数の個人主体**：例えば当該議題の主要参加者が、それぞれ自身のこれまでの関連協働の MeriToken エントリを援用する；
- **入れ子参照**：上記の `Fay` 主体自身が、いくつかの個人主体の MeriToken エントリを代表権の根拠として参照している。

このような高密度参照が同一議題、同一時期、同一開示面の内側で同時に発生すると、MeriToken の機構の幾つかの性質が同時に圧力の極限に押し付けられる。

**機構の再吟味**：

- **参照集約の境界**：各 `Fay` 主体の集約型参照それ自体がすでに複合的な参照面である（[04-meritoken-usage.md](./04-meritoken-usage.md) の「`Fay` 主体の参照方法と応用シーン」節を参照）。複数の `Fay` 主体の複合参照面が同一議題下で重畳する場合、外部の吟味者が必要とするのは「各 MeriToken を逐一展開する」ことではなく、「これらの集約面が互いに矛盾しないことを、詳細を展開せずに確認できるか」である。これは集約型参照が「集約レベルの照合可能性」を支えねばならないことを意味し、単条レベルの検証可能性だけでは足りない。
- **開示分級の協調**：高密度利用の下では、各被参照側（個人主体または下位の `Fay` 主体）の開示許諾の段階はそれぞれ異なりうる。集約側は高開示と低開示を混ぜて対外提示してはならない。さもなければ低開示を強制的に高めることと等価になる。テーマ A は「最小開示段階のフォールバック」原則を要求する——集約面の対外開示段階はその中の任意の被参照エントリの最小許諾段階を上回らず、すべての被参照側が積極的に同意した場合に限り全体としての段階引上げを行う。
- **撤回経路の波及**：底辺の個人主体が開示許諾を撤回するとき、当該エントリに依存するすべての `Fay` 主体の集約面は同時に対応する分量を失効させなければならない。「上流が撤回したのに下流の集約はキャッシュの形で晒し続ける」という事態は許されない。これにより [02-meritoken-technical.md](./02-meritoken-technical.md) の「プライバシー保証」節の「撤回と失効」意味論を入れ子状況へと拡張する。
- **取得記録の可読性**：高密度シーンでは、各参照を `GMC` で記録すると単一議題の記録量が急速に膨張する。機構レベルの記録は依然として必要だが、人間に提示する際は「議題—主体—時間」の三軸でたたみ、生のままの記録に監査プロセスが埋もれないようにする必要がある。

**未解決点**：

- 集約レベルの照合可能性を具体的にどの一群のコミットメント機構が担うかは、`GMC` 上位ルールと共に設計する必要がある；
- 「最小開示段階のフォールバック」と、特定参加方が全体としての段階引上げを望む場合の協議フローは、それ自体が MeriToken エントリの形式で記録される必要がある；
- 記録のたたみ込みの提示ルールはプロトコル層の問題ではないが、ブループリントに付随するツールチェーンが統一的に取り決める必要がある。

### テーマ B：ローリングシーン

**負荷の源**：長期ライフサイクルのプロジェクトでは、MeriToken は「一度の貢献—一度の評価—一度の記録」の最小単位に留まらず、長時間スケールで累積、修正、撤回、アーカイブを循環的に繰り返すことになる。典型的な情境としては、世代をまたぐ公共プロジェクト、長期に進化するオープンソース協働、複数期にわたる参加者を抱えるコミュニティ統治がある。この種のプロジェクトがもたらす負荷は、もはや単発参照の複雑さではなく、長時間スケールにおける機構の自己整合性である。

**機構の再吟味**：

- **累積**：プロジェクトの各段階で新たな MeriToken エントリが沈殿し、それらは `GMC` の記録に従い、段階の切替により失われない。しかしプロジェクトの対外的な「全体像」は、すべてのエントリを差別なく積み重ねることを避ける必要がある。段階別、役割別、議題別の階層化された組織化が不可欠である。これは [03-meritoken-social.md](./03-meritoken-social.md) の「個人成長マッピング」節における「単点能力から多次元像へ」の発想と一致するが、プロジェクト側では `Fay` 主体が階層化集約の役を担う必要がある。
- **修正**：既存の MeriToken エントリに対し、事実層で新たな見届け、新たな評価、新たな対照が現れた場合、元のエントリを上書きするのではなく、修正エントリを追記する形で対応すべきである。修正エントリも MeriToken エントリの一種であり、修正理由と多者共同署名を含む。読者は時系列に沿って元のエントリと後続の修正の双方を確認でき、「単一エントリの繰り返しの書き換えで歴史を均してしまう」状況を避けられる。
- **撤回**：長期ライフサイクルでは、撤回は開示許諾の撤回だけでなく、原エントリの効力の撤回（発行側の離脱、協働前提の変更等）も含む。効力の撤回は記録を削除しないが、エントリの状態層に「撤回済」と注記される。後続の参照側は「撤回前の参照」と「撤回後の参照」を区別できる必要がある。撤回操作それ自体は [05-meritoken-credential.md](./05-meritoken-credential.md) の「境界と対応位置づけ」節で定義した独立撤回経路に従い、`credential` の回収経路と互いに代償しない。
- **アーカイブ**：プロジェクトが段階的に終了するか、全体として終了する際、関連する MeriToken エントリは抹消されるのではなくアーカイブ状態に入るべきである。アーカイブ状態のエントリはなお独立に検証され、援用されうるが、デフォルトの開示段階は最小に下がり、長期プロジェクト終了後何年経っても高開示段階で参加者を晒し続けないようにする。アーカイブへの状態遷移そのものも `GMC` 上に記録され、「ある時点を境に、エントリが密かに可視性を変える」という不透明性を回避する。

**機構の自己整合性**：累積 / 修正 / 撤回 / アーカイブは一つの完結した循環を構成し、各動作が新たなエントリの形式で記録される。これにより「時間」という次元それ自体が MeriToken の機構に組み込まれ、外部からプロジェクト側が一方的に制御するものではなくなる。時間次元上のあらゆる状態変化が独立に検証可能となり、プロジェクト側の解釈に依存しない。

**未解決点**：

- 修正エントリの多者共同署名範囲が、原エントリと厳密に同一でなければならないかは、シーンに応じて細分化する必要がある；
- アーカイブ転換時のデフォルト開示段階を、プロジェクト側と参加者が集合的に調整できるかどうかは、協議フローを与える必要がある；
- 段階横断参照の重みが時間と共に減衰するか否かは、個別プロジェクトの方針選択であり、ツールチェーンに支援されるべきであってプロトコル層に強制されるべきではない。

## 用語脚注

本書に登場する `Reserved_Term`：

- **GMC**：Global Merit Chain、MeriToken の上位体系。詳細は [glossary.md](./glossary.md) を参照。
- **Fay**：非個人主体の MeriToken 参照者。詳細は [glossary.md](./glossary.md) を参照。
- **credential**：個人または `Fay` 主体の身元と権属を裏付ける資格情報。詳細は [glossary.md](./glossary.md) を参照。
- **ifay**：プロジェクト体系の名称。詳細は [glossary.md](./glossary.md) を参照。

MeriToken の中国語主称呼は `zh-CN` と `zh-TW` のブループリント本文においてのみ MeriToken の通常呼称として用いられる。詳細は [glossary.md](./glossary.md) の `Localized_Term` 節を参照。
