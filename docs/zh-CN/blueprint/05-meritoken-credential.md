# 05 credential 与美誉值的关系

> 简介段：本篇承接 [01-meritoken-overview.md](./01-meritoken-overview.md) 的位置定义，在「契约部件」语义下，专门处理美誉值（MeriToken）与 `credential` 之间的边界与对位关系。两者经常被混用，但在新社会的协作实务中如果不分清，会同时削弱身份与权属的稳定性、以及贡献与评价的可累计性。

## 背景

新社会中关于「我是谁」「我能不能做这件事」「我做过什么」「我做得怎么样」这几个问题，必须有结构上彼此独立、又能互相组合的承载对象。如果把所有问题都堆给一类对象去回答，就会出现两类典型偏差：

- **凭据膨胀**：把「我做过什么、做得怎么样」也写进 `credential`，使得身份与权属凭据被迫不断签发与更新，凭据签发方负担过重，凭据持有方也失去对自己评价记录的支配权。
- **评价漂移**：把「我是谁、我有什么权属」也写进美誉值，使得贡献评价的容器被身份属性挤占，原本应当由协作多方共签的评价记录被身份签发权所稀释。

蓝图把这两类对象分开承担，并明确：`credential` 解决「身份与权属」一面，美誉值解决「贡献与评价」一面。两者各自独立又彼此对位。本篇的任务是把这条边界讲清楚，避免后续 06–07 篇与各语言扇出版本在引用时出现混用。

`credential` 的具体协议层细节由 ifay 体系的官方文档承担，本篇只在「与美誉值边界」必要的范围内给出最小说明。

## 核心内容

### credential 的角色定位

`credential` 解决「主体是谁、对什么对象拥有什么权属」这一类问题，是新社会中身份与权属的承载凭据：

- **身份与权属的可证明位**：`credential` 由具备签发资格的主体签发，记录被签发主体的身份属性（如成员身份、角色、资质）或对特定对象的权属（如对某资源、某协议位、某协议角色的支配权）。它回答的是「这位主体在某一时点对某一对象处于什么权属状态」。
- **由凭证与代币层签发、验证、回收**：`credential` 的生命周期由凭证与代币层的协议规则约束。签发动作明确了其有效范围；验证动作让任意第三方可以独立确认凭据的存在与归属；回收动作让签发方在权属变更时能够及时收回凭据，避免凭据脱离实际权属继续被援引。
- **侧重于「能做什么」的入口资格**：在跨主体协作中，`credential` 通常作为入口资格被检视：被检视方持有相应 `credential`，意味着它在制度上具备进入某一协作面、援引某一协议位、调用某一资源接口的资格。`credential` 不直接评价被检视方过去做得如何。
- **稳定性优先**：`credential` 的语义稳定性是其根本属性。一份长期有效的成员资格、一份对某资源的支配权，不会因为持有方短期内的协作表现而频繁波动；波动的部分应当由美誉值承载，而不是反映回 `credential`。

把 `credential` 的角色锁定在「身份与权属凭据」这一面，是为了让凭据的签发与回收路径保持简洁可审计，不被频繁的评价记录所干扰。

### 美誉值（MeriToken）的角色定位

美誉值解决「主体做过什么、被如何评价」这一类问题，是新社会中贡献与评价记录的承载对象：

- **贡献与评价的可累计位**：美誉值由协作多方共签产生（详见 [02-meritoken-technical.md](./02-meritoken-technical.md) 的「加密」与「取用」段），记录的是「在某一具体协作中，谁贡献了什么、谁见证了什么、谁如何评价」。它回答的是「这位主体过去在哪些具体协作中表现如何」。
- **从属于 `GMC` 上位体系**：与 `credential` 的签发—回收链路不同，美誉值的产生—引用—撤回链路在 `GMC` 上位体系下统一记账，按链式语义保证全网一致与不可篡改（详见 [01-meritoken-overview.md](./01-meritoken-overview.md) 的「美誉值（MeriToken）与 `GMC` 的从属关系」段）。
- **侧重于「做过什么、做得怎么样」的过程留痕**：美誉值不充当入口资格的检验，而是在协作过程中持续生成。它对外可以被援引、被聚合、被对照，但每一条都对应具体的协作事实，不可凭空增减。
- **可累计、可撤回、可分级披露**：美誉值在长期协作中累计形成多维度成长画像；当原始约定改变时，被引用方可以撤回相应披露许可；任何引用都按 `GMC` 留痕（详见 [02-meritoken-technical.md](./02-meritoken-technical.md) 的「隐私保证」段）。

把美誉值的角色锁定在「贡献与评价记录」这一面，是为了让协作过程的细粒度评价能够长期累计、独立支配，不被身份签发权所兼并。

### 边界与对位关系

`credential` 与美誉值在新社会的协作中各自承担不可互相替代的角色。下表沿五条语义轴并置两者的差异：

| 语义轴 | `credential` | 美誉值（MeriToken） |
|--------|--------------|---------------------|
| 语义焦点 | 身份与权属凭据，回答「主体是谁、对什么对象拥有什么权属」 | 贡献与评价记录，回答「主体在哪些协作中做过什么、被如何评价」 |
| 生命周期 | 由凭证与代币层签发、验证、回收，强调入口资格的状态切换 | 由 `GMC` 上位体系记账，产生—引用—撤回链路按链式语义留痕 |
| 持有形态 | 由签发方与持有方双向锚定的状态对象，强调稳定性 | 由协作多方共签的过程对象，强调累计性 |
| 引用方式 | 在协作入口处被检视，验证「是否具备资格」 | 在协作过程或事后被援引、聚合、对照，呈现「过去做得如何」 |
| 跨主体语义 | 同一主体在不同协作面持有不同 `credential`，相互之间不一定可比 | 同一主体在不同议题上累计的美誉值条目可被跨议题引用，但不会自动迁移评价权重 |

边界在四个层面互相支撑，确保两类对象不被混用：

- **不可互相替代**：`credential` 不能用来记录「我做过什么、做得怎么样」，否则就会出现凭据膨胀与签发方负担失衡；美誉值不能用来记录「我是谁、我有什么权属」，否则会出现评价漂移与所有权稀释。两者各自承担不同的制度任务。
- **互为前提与延展**：在很多协作中，`credential` 提供入口资格，美誉值在入口之内沉淀过程留痕。例如某项跨组织议事，`credential` 决定参与方是否具备发言资格；美誉值则记录每一次发言的贡献与评价，长期累计后影响后续议题的发言权重（参见 [03-meritoken-social.md](./03-meritoken-social.md) 的「政治逻辑」段）。
- **统一引用、分别承载**：在 `Fay` 主体的代理式与聚合式引用（详见 [04-meritoken-usage.md](./04-meritoken-usage.md) 的「`Fay` 主体的引用方式与应用场景」段）中，对外往往同时呈现一组 `credential` 与一组美誉值条目。前者用于证明 `Fay` 主体具备代表权，后者用于呈现其历史协作面貌；两者并列引用而非合并。
- **撤回路径独立**：`credential` 的回收由签发方按权属变更触发；美誉值的撤回由被引用方按披露许可触发。两条撤回路径不应互相代偿——签发方不能通过收回 `credential` 抹除已经被见证的美誉值条目；被引用方也不能通过撤回美誉值披露反推签发方收回 `credential`。
